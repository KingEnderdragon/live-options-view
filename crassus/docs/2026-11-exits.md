# Configurable profit-taking and protective exits (issue #86)

The option books in this repo close reactively: a strategy sells when its own
signal stops supporting the position. Nothing closes a position because it has
made enough money, because it has lost too much, or because the contract's
remaining premium should be salvaged before expiration. The mandatory
end-of-day flatten bounds *time*; Guideline Phelps withholds a signal-driven
exit for one window. This document describes the layer that fills the gap
between them: `crassus/exits.py`, wired into the runner between the flatten and
the account's strategy.

It is implemented, tested and **inert** in this branch. Nothing changes for a
deployed bot until `CRASSUS_EXITS_ENABLED=1` is set after review; the numbers
below are a proposal with stated rationale, not a tuned result.

## What it does

Every cycle, for each account whose strategy is covered, the runner values each
held position against a fresh liquidation-side quote, compares that to the
position's documented average cost, and closes the most urgent triggered
position:

| Held position | Liquidation price | P&L |
| --- | --- | --- |
| Long (quantity > 0) | quote **bid** | `(bid - average_cost) / average_cost` |
| Short (quantity < 0) | quote **ask** | `(average_cost - ask) / average_cost` |

The quote must pass `Quote.is_executable` -- both sides present and no older
than the Worker's own 15-second execution cutoff, measured on the server clock.
A trigger with no usable quote does not fall through to the strategy: the cycle
returns an explicit `no_trade` naming the stuck symbols, so the strategy cannot
open a fresh position while a position that wants out has no price.

Cost basis is `client.Book`'s average cost, reconstructed each reconciliation
from the server's authoritative trade history. The Worker settles paper options
in premium terms, so the percentage is premium P&L and no contract multiplier
enters the threshold arithmetic.

## Precedence

Highest first. Implemented order in `Runner._run_account`:

1. **Session** -- `maybe_flatten` runs first and always wins. This layer never
   preempts it, duplicates it, or opens a position inside the flatten window.
2. **Protective stop** -- fires by default even inside a Guideline Phelps
   window. Phelps deliberately tolerates discomfort and has no loss bound; a
   stop whose whole purpose is bounding loss cannot be subject to it.
   `stop_bypasses_phelps: false` opts an account into strict doctrine, at the
   cost of an unbounded loss inside the window.
3. **Profit target** -- deferred by default inside a Phelps window. Taking a
   profit is not the capitulation Phelps protects against, but closing early
   also ends the convexity purchase the method paid for. Set
   `profit_bypasses_phelps: true` to let the target fire regardless.
4. **Signal reversal** -- the base strategy's own sell, with Phelps's existing
   deferral unchanged. This layer never suppresses or rewrites it.
5. **Re-entry** -- after an exit is submitted, the same contract is blocked for
   `reentry_cooldown_minutes`. The block is recorded before submission, so it
   holds even when the exit is rejected or its outcome stays ambiguous; the
   record is durable and survives a restart.

Multiple positions in one book are evaluated every cycle; one leaves per cycle
(`Decision` carries one symbol). Stops outrank profit targets, and within a
trigger class the larger absolute move leaves first.

## Proposed defaults and why

| Setting | Default | Rationale |
| --- | --- | --- |
| `profit_target_pct` | `0.50` | A 0DTE ATM contract gaining half its premium is a large intraday move; 50% is conservative against +100%, and well above the 20% the Cheshire straddle already uses as its core-profit threshold (`looking_glass_straddle.DEFAULT_CORE_PROFIT_THRESHOLD_PCT`), so a signal book is not nickeled out by its own exit. |
| `stop_loss_pct` | `-0.50` | Symmetric with the target: half the debit. Wide for a same-day contract, but real. Today's alternative is no bound at all. |
| `reentry_cooldown_minutes` | `15` | Three runner cycles at the deployed five-minute interval: long enough that an unchanged stale signal cannot buy the same contract straight back, short enough that a later genuine setup is not blocked. |
| `stop_bypasses_phelps` | `true` | See precedence above: a stop exists to bound loss; Phelps has no loss bound. |
| `profit_bypasses_phelps` | `false` | Doctrine-consistent default: the window is the convexity purchase. |
| `quote_max_age_s` | not configurable | It is the Worker's execution contract (15 s); a looser local value only produces 409s. |

Nothing in the repository establishes better values: the straddle's 20% is a
different product, and the Phelps 27.5-minute window is a hold-time, not a
return, benchmark. These are review questions, and the defaults are inert until
approved.

## Configuration

Per account, in `accounts.example.json` (or an ignored `accounts.json`
override):

```json
{
  "alias": "Luigi",
  "username": "crassus_luigi",
  "strategy_id": "reddit_sentiment_qqq",
  "password_env": "CRASSUS_PW_LUIGI",
  "exits": {
    "profit_target_pct": 0.5,
    "stop_loss_pct": -0.5,
    "reentry_cooldown_minutes": 15,
    "stop_bypasses_phelps": true,
    "profit_bypasses_phelps": false
  }
}
```

Unknown keys, non-numeric values, a non-positive target, a non-negative stop and
a negative cooldown are configuration errors recorded against that account
only (`runner_error`, reason `Invalid exit configuration: ...`), never a
process-wide crash and never a silent fallback.

### Coverage

On by default (when activated) for the signal-reversal option books:
`reddit_sentiment_qqq` and its `_phelps`/`_fixed_window` variants,
`trump_whisperer_qqq` (and variants), `momentum_qqq` (and variants),
`momentum_puts_only_qqq`, `max_pain_qqq`, `oi_skew_qqq`,
`put_call_ratio_qqq`, `phelps_pure_qqq`.

Deliberately excluded:

* `smoke_atm_roundtrip*` -- pipeline instruments whose round trip is the point,
  and whose fixtures prove the lifecycle.
* `canopus_down_day_14` and `looking_glass_straddle` -- already own their
  terminal/profit exits; a second policy owner on one position is a defect.
* `spy_sma200_double_or_out` -- SPY200's double-or-out rule is a distinct,
  approved strategy with `overnight_hold`; it must not acquire an intraday exit.

Any excluded strategy can opt in with `"exits": {"enabled": true}` once
activated.

## Activation and rollback

The layer requires `CRASSUS_EXITS_ENABLED` to be an explicit affirmative
(`1`, `true`, `yes`, `on`). Absent or anything else keeps it inert, including a
per-account `enabled: true` -- activation is a deployment decision, not a
catalog accident.

1. Review the numbers and precedence above; adjust per account if wanted.
2. Set `CRASSUS_EXITS_ENABLED=1` on the Railway service and restart.
3. Verify the first cycle: a held position with no trigger produces an ordinary
   strategy decision; a triggered one produces `strategy_id: exit_policy` in the
   ledger with the full audit metadata.
4. Rollback: unset the variable (or set it to `0`) and restart. No state needs
   cleaning: `state/exits.json` only carries cooldown timestamps and is pruned
   after 24 hours.

## Audit trail

An exit decision's metadata carries `exit_trigger`, `exit_symbol`,
`exit_held_quantity`, `exit_cost_basis`, `exit_liquidation_price`, `exit_bid`,
`exit_ask`, `exit_quote_age_s`, `exit_pnl_pct`, `exit_threshold_pct` and the
resolved `exit_policy`. The ledger row records the decision, the submitted
intent's `execution_request_id`, the HTTP status, the outcome class and the
resulting account state, and the decision's `strategy_id` is `exit_policy` -- so
an exit is attributable separately from the account's assigned strategy.

## Tests

`python scripts/verify_exits.py` (33 checks) covers inclusive boundaries for
both triggers, long and short holdings priced on the correct side, multi-contract
books with stop-over-profit precedence, stale and missing quotes, quote errors,
the two Phelps bypasses and the unknown-entry-time case, configuration
validation, inertness without activation, the re-entry cooldown across a
restart and its non-interference with reducing trades, audit-field completeness,
and two runner-level scenarios: an exit becoming a real submitted sell
attributed to `exit_policy`, and an invalid `exits` block becoming a per-account
`runner_error` instead of a trade.

## Not established here

No live or paper trade has been executed under this policy. The evidence is
unit and runner-level with fixtures; the live behaviour to watch after
activation is whether a stop and the Phelps window interact as intended on a
real 0DTE position, and whether the 15-minute cooldown ever blocks a
genuinely new setup. Those are observations for the live checks, not claims of
this branch.
