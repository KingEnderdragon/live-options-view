# TimeAndSale probe — access evidence, 2026-11-09

Read-only investigation of the documented same-feed `TimeAndSale` route for
extended-hours equity prices. No provider, account or credential change was
made.

## What the documentation establishes

- tastytrade's DXLink streamer documents `TimeAndSale` as an event type and
  `FEED_SUBSCRIPTION` accepts any dxFeed event type, including `TimeAndSale`
  (`developer.tastytrade.com/asyncapi/tastytrade-streaming.asyncapi.json`).
- dxFeed's `TimeAndSale` carries a provider `time`, `tradeId`, an
  `extendedTradingHours` flag and a `type` of NEW / CORRECTION / CANCEL
  (`docs.dxfeed.com/dxfeed/api/com/dxfeed/event/market/TimeAndSale.html`).
- The same tastytrade document's own `FEED_SETUP` example subscribes
  `TradeETH`, so the extended-trade event type is an expected part of this
  gateway's event set rather than an undocumented extension.

## What this does not establish

It does not establish that the account's feed delivers `TimeAndSale` prints for
US equities during extended hours, nor that it refuses them. The implementation
below therefore treats the route as unproven: it is isolated on its own channel
so a refusal cannot disturb the accepted quote/trade feed, and the deployment
reports `timesale.subscribed`, `timesale.error`, `timesale.counts` and
`event_fields` so the first real session answers the question with data.

## Owner action if the counters show no prints

1. Confirm `timesale.subscribed` is true and `timesale.error` is null. A
   non-null error names the channel-level refusal exactly.
2. If subscribed but `counts.received` stays zero through a full extended
   session, the feed is not delivering TimeAndSale for these symbols; record the
   window and symbols, then test a single-symbol probe with `TradeETH` and
   `TimeAndSale` before concluding anything about entitlement.
3. Only after those two steps would a provider/data-package change be a
   justified proposal; nothing in this branch requires or requests one.

## Protocol notes that shaped the probe

- dxLink requires **odd** numbers for service channels, so the probe uses
  channel 3 alongside the accepted channel 1; channel 2 would be a protocol
  violation.
- The `TimeAndSale` flags word carries the transactional type
  (NEW/CORRECTION/CANCEL), the extended-hours bit, the valid-tick bit and the
  spread-leg bit. Identity is the unique per-symbol index (time + sequence) or a
  non-zero `tradeId`; `tradeId` 0 means unavailable.
