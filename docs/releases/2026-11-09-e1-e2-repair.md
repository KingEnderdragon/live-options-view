  `observed_at` between `20:59:59.909Z` and `20:59:59.965Z` — the 16:00 ET

- `price_lane_health.json` at `23:40:16Z`: `contracts` null for all seven

## Causes

**E1 — equity extended hours.** The lane selects the last trade whenever one
exists, regardless of session. In the observed after-hours window no
extended-hours trade print arrived for any of the 71 streaming equity rows, so
`last_trade` could only ever be the 16:00 ET close. Quotes carried no
observable provider timestamp in that window. This is consistent with dxFeed's
documented semantics — TradeETH is the extended-hours last trade, and during
extended hours the Trade event updates only volume and turnover — but the
observation alone does not establish that this gateway cannot deliver the
event. Feed health now records event counts and observed field names per event
type so a deployment settles the schema question with data.

**E2 — futures.** `resolve_futures()` cleared `RESOLVED_CONTRACTS` and set every
futures `PRICE_TICKERS` entry to `None` *before* the provider request. The
17:54:07Z six-hour reconciliation produced no usable answer, the lane compared
its mapping with the resulting null snapshot, rebuilt its feed without futures
symbols, and had no retry until the next six-hour tick. The 23:54:13Z retry also
failed because the lane reused the access token issued at startup; tastytrade
access tokens last 15 minutes. Publication and health stayed green throughout;
only observations froze.

## Review repairs after the first return

Independent review of `569bf1c` reproduced two blockers:

- a complete futures map whose resolution degraded kept its preserved snapshot,
  so the "unchanged and complete" branch cleared the retry deadline the outcome
  handler had just set; the deadline now clears only when the resolver reports
  `ok`, and the lane retries on the ladder while degraded;
- `_resolution_token` renewed the access token but did not persist it, so the
  next attempt 61 seconds later reused the expired one; the renewed payload is
  now persisted for later REST attempts, and a rebuild after renewal uses the
  renewed streamer credentials.

Adjacent paths are covered too: a genuine contract change is actionable while a
retry is pending (only a failed replacement feed suppresses another attempt); a
simultaneous loss and roll rebuilds and keeps the retry; a failure with an
expired known contract never mutates the map; and the backoff ladder grows then
resets after a successful resolution.

## Changes

`market_data/live_market/prices.py`

- session-aware selection: a last trade is current only with a provider event
  time inside the active session; in premarket/after-hours a qualified
  two-sided quote becomes the price (`bid_ask_midpoint`), with `observed_at`
  from the older side only when both sides carry provider time, otherwise
  `null` + `provider_quote_time_unavailable`;
- quote gates: both receipts inside the feed stale window
  (`EXTENDED_QUOTE_MAX_AGE_SECS`) and spread at or under
  `EXTENDED_QUOTE_MAX_SPREAD_PCT`; otherwise the honest stale close is kept;
- receipt time is never promoted to observation time; regular-session,
  futures, crypto, FX and daily rows keep their existing selection;
- SPY keeps its accepted midpoint-first selector.

`market_data/live_market/price_sessions.py`

- `EXTENDED_STATUSES`, `equity_session_start()`, `session_start_for()`; the lane
  publishes per-label `session_starts` so selection compares provider event
  time with the actual session start (early closes included).

`market_data/live_market/overview_sources.py`

- `resolve_futures()` is transactional: candidates are built off to the side
  and committed only after a usable answer; failures and empty answers preserve
  the last good mapping and record a bounded retry (60 s → 900 s);
- a still-valid prior contract is carried for an unresolved product, an expired
  prior is dropped; `resolution_status()` exposes state, error, retry and
  per-label symbols.

`market_data/live_market/price_lane.py`

- a snapshot that only loses contracts is a resolution gap, not a roll: keep
  subscriptions, record `contract_gap_reason`/`contract_retry_at`, retry on the
  bounded cadence; recovery rebuilds once;
- replacement feeds start before the old one stops, so a failed rebuild keeps
  the previous subscriptions streaming;
- health adds `contract_resolution`, `contract_gap_since`, `contract_retry_at`,
  `contract_gap_reason`.

`market_data/live_market/feed.py`

- per-event-type counters and quote provider-time counts in feed health, so the
  provider question ("is TradeETH delivered? do quotes carry times?") is
  answered by data instead of inference;
- an isolated `TimeAndSale` channel: its own odd service channel (3, as the
  dxLink protocol requires) with its own `FEED_SETUP` (`time`, `sequence`,
  `price`, `size`, `tradeId`, `flags` plus the derived flags fields) so a
  rejection cannot disturb channel 1; provider-index/tradeId identity,
  documented NEW/CORRECTION/CANCEL handling, valid-tick and spread-leg
  rejection, cancellation without a price, out-of-order prints ignored, and
  counts plus any channel error in health.

`market_data/live_market/prices.py` (print selection)

- an extended-session print replaces the unknown-time midpoint only when its
  provider time is inside the session, the provider did not mark it
  regular-session, and it is newer than the snapshot Trade; the receipt time
  stays a receipt. `PRICE_LANE_TIMESALE=0` turns the probe off.

## Compatibility

No published field was removed or renamed. `price_basis` remains within the
consumer's accepted whitelist (`bid_ask_midpoint` already existed for SPY).
Health additions are additive JSON keys; the MCP consumer ignores unknown
health fields. `market_mcp/overview.js` and `site/**` were not touched.

## Activation and rollback

No new required configuration. The change ships with the collector image on the
normal release path; `PRICE_LANE_ENABLED` and all schedules are unchanged. The
TimeAndSale probe can be disabled at runtime with `PRICE_LANE_TIMESALE=0` if the
extended session shows it is not useful.

Rollback is a normal revert to `014b48ad`. Reverting restores the 16:00-close
selection for after-hours equities and the six-hour, non-transactional futures
resolution. No environment variable, credential or schedule change is involved.
